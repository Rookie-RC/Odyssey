# Odyssey 路线图：给留学生的旅行足迹地图

> 本文记录产品方向、已经完成的部分，以及接下来分阶段要做的事。怎么部署成网站，见 [DEPLOY.md](DEPLOY.md)。产品与视觉的权威规范仍然是 [PRODUCT_SPEC.md](PRODUCT_SPEC.md) 和 [design/VISUAL_SPEC.md](design/VISUAL_SPEC.md)。

## 1. 定位

**一句话**：留学这几年，你在世界上留下的足迹。

面向从中国出发、在欧洲或北美读书的留学生，记录三件事：

1. **什么时候出国、什么时候回国**：每段留学（本科、硕士、交换）从抵达到最终回国，以及中间每次回国过假期。
2. **这期间去过哪里、为什么去**：深度旅行、一日游、只是路过住一晚、转机，以及每次是去滑雪、冲浪、Citywalk、看展还是野餐。
3. **还想去哪里**：按季节排好的心愿，比如冬天去 Lofoten 追极光，夏天去撒丁岛。

它不是攻略工具、行程规划器或社交平台。它是一本**自己的地图集**：打开是一张地图，往下是时间线，再往下是下一站。

**形态：网页优先，不做原生 App。** 一个网址，电脑和手机都能打开；手机上「添加到主屏幕」后像 App 一样全屏使用（PWA），不需要上架 App Store 或 Google Play。以后再做微信小程序，和网页共用同一套后端和数据。

## 3. 正式上线前必须做的

这些是「能给同学用」之前的硬门槛，详见 DEPLOY.md 第 8 节：

1. **换底图**：Carto 免费底图只允许非商业使用且有访问量上限。候选：OpenFreeMap（免费、无 key）、MapTiler（免费额度）、自托管 Protomaps。`lib/map-style.ts` 的主题适配要跟着改。
2. **换地点搜索**：Photon 公益接口不适合正式流量，改用 MapTiler Geocoding 或自托管。
3. **找回密码和邮箱验证**：需要接一个发邮件的服务。
4. **隐私政策和用户协议**。
5. **新用户引导**：第一次登录时问三个问题——你在哪个城市读书、什么时候出国、家在哪里，直接生成第一段「留学时光」和地图上的第一个点，而不是面对一张空地图。

## 4. 接下来的阶段

### 阶段 A：小范围内测（先给身边同学用）

- 部署到香港或新加坡节点（国内外都能访问，不需要备案），关闭公开注册（`-allow-signup=false`），手动给同学开账号。
- 完成上面第 3 节的 1–5。
- 观察：大家实际会记录多少地点、卡在哪一步、最想分享什么。

### 阶段 B：让记录变得轻松

记录成本是这类产品最大的流失点，优先降低它：

- **从照片导入**：选一批手机照片，在浏览器里读取 EXIF 的时间和 GPS，自动聚类成「某年某月去了某城市」，用户确认即可生成到访记录（照片不必上传就能识别）。
- **三步快速添加**：搜城市 → 点玩法图标 → 选月份，手机上单手完成。
- **地图按玩法筛选**：只看滑雪、只看海边。
- **更多玩法**：看球、潜水、圣诞市集、音乐节、自驾……词表在 `lib/activity.ts`，后端只校验格式，加新玩法不用改后端。

### 阶段 C：分享与传播

留学生最常见的分享场景是小红书和朋友圈：

- **留学足迹海报**：「留学 732 天 · 14 个国家 · 37 座城市」配地图和玩法图标，导出 3:4 竖版图（小红书）和长图（朋友圈）。现有的票根分享图可以直接扩展。
- **只读分享链接**：生成一个公开链接给家人朋友看，可以选择隐藏具体日期。
- **年度回顾**：每年年底自动生成「这一年你去了哪里」。

### 阶段 D：同学之间（谨慎）

- 好友互看地图、「我们一起去过的地方」、同校同城的人去过哪里。
- 社交功能会显著增加隐私、内容审核和运营成本，等前面阶段验证之后再决定做不做。

### 阶段 E：微信小程序

- 小程序和网页**共用同一套后端 API 和账号数据**，小程序端只需要重写界面（地图用微信自带的腾讯地图组件，不能直接用 MapLibre）。
- 前提条件：
  - 小程序请求的服务器域名必须是 HTTPS 且**已做 ICP 备案**，实际上需要一台中国大陆服务器（或腾讯云托管）。
  - 小程序本身也要备案；个人主体能选的服务类目有限制，记录旅行、上传照片这类功能能否以个人主体上线需要提前核实，可能需要企业主体。
  - 用户数据如果同时存在海外和国内服务器，需要评估跨境数据和《个人信息保护法》的要求。
  - 登录：小程序用 `wx.login` 绑定到已有账号，网页端保留邮箱登录。
- 建议在阶段 C 之后、确认有足够用户再启动。
